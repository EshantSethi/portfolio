03. Projects

Shortly – Production URL Shortener

Java 21 · Spring Boot 3.5 · PostgreSQL · Redis · React 19 · Docker · GitHub Actions

GitHub ↗ Live Demo ↗
  • Full-stack URL shortener serving live traffic: Spring Boot API on Render, React frontend on Vercel, PostgreSQL on Neon, Redis on Upstash.
  • 5 REST endpoints: custom aliases, link expiry and QR code generation, with global exception handling.
  • Redis cache-aside with TTL eviction gives redirects under 10ms and cuts PostgreSQL reads by about 70%.
  • Rate limiting built from scratch (sliding window, per IP). Found and fixed a race condition in concurrent map eviction.
<10ms cached redirects ~70% fewer DB reads CI/CD + Docker
React (Vercel)→ Spring Boot API (Render)→ Redis cache (Upstash)→ PostgreSQL (Neon)

The problem

Long links are hard to share. A short-link service has to redirect very fast and handle a lot of traffic, but hitting the database on every click would make it slow and costly.

What I built

A full-stack shortener with 5 REST endpoints (custom alias, link expiry, QR codes) and click tracking in PostgreSQL. Popular links are kept in Redis, so most redirects never touch the database. It ships through GitHub Actions and Docker.

Hardest challenge

I wrote my own rate limiter (a sliding window per IP). Under load, some requests failed at random. I traced it to a race condition: old entries were being removed from a shared map while other threads were still using them. I fixed the removal logic so it's safe when many requests run at once.

Result

  • Cached redirects in under 10ms
  • ~70% fewer database reads
  • Limits of 20 writes and 60 reads per minute per IP
  • Live and serving real traffic

InsightRAG – RAG Backend in Java

Java 21 · Spring Boot 3.3 · LangChain4j · PostgreSQL (pgvector) · BM25 · Docker · JUnit 5

GitHub ↗
  • Modular RAG backend with a REST API, in-process embeddings, pgvector storage, intent routing and a read-only SQL tool.
  • Hybrid search (vectors + BM25 built from scratch) combined with Reciprocal Rank Fusion and re-ranking.
  • Abstention gate and grounding checks cut confident hallucinations from 7 to 0.
  • Covered by 33 JUnit 5 tests, with per-query tracing, Docker and GitHub Actions CI.
Precision 0.25 → 0.58 MRR 0.72 → 1.00 Hallucinations 7 → 0
Question→ Intent router→ Vectors + BM25→ RRF + re-rank→ Abstention gate→ Answer

The problem

AI models often give confident answers even when they're wrong. I wanted a Java backend that answers only from real documents, and says "I don't know" when it isn't sure.

What I built

A modular Spring Boot RAG service. It stores document embeddings in pgvector, routes each question by intent, and can also run a safe, read-only SQL tool. Each part is a separate, reusable component.

Hardest challenge

Vector search alone often found the wrong chunks (precision was only 0.25), and the model made up answers in 7 of 25 test cases. I wrote BM25 keyword search from scratch, merged it with vector results using Reciprocal Rank Fusion, and added a gate that checks both confidence and keyword coverage before answering.

Result

  • Precision 0.25 → 0.58
  • MRR 0.72 → 1.00
  • Hallucinations 7 → 0, with no over-cautious refusals
  • 33 JUnit tests and a 25-case evaluation harness
